# voidImageViewer 2.4 多格式扩展开发计划与技术报告

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 在维持 `voidImageViewer` 极致轻量（小体积、低内存、毫秒级启动）的前提下，为 Windows 桌面看图场景扩充 6 大核心扩展格式：**APNG、TGA、WMF/EMF、CUR/ANI、HEIC/HEIF、AVIF**。

**架构：** 采用纯 C / Win32 原生 API 解耦设计。基于模块化注册表模式扩展文件头 Magic Number 检测与扩展名关联，静态格式统一解包为 Win32 32-bit DIB/HBITMAP 位图，动画格式复用 GIF/WebP 现有的 `viv_animation_t` 计时混合循环器；特定格式（HEIC/WMF/EMF）充分调用 Windows 系统 WIC/GDI 原生组件，实现零体积与 GPU/系统硬解集成。

**技术栈：** C99, Win32 API, GDI/GDI+, Windows Imaging Component (WIC), `libavif` + `dav1d` (仅 AVIF 引入)。

## 一、 整体架构设计与流程流转

为了保证扩展新格式时不破坏已有代码的高性能与稳定性，整体扩展架构分为四层：

```
┌─────────────────────────────────────────────────────────────────┐
│                      1. 文件识别与魔数检测 (Magic Identification) │
│  - 扩展名判断 fallback -> 快速读取前 16 字节 Magic Header         │
├─────────────────────────────────────────────────────────────────┤
│                      2. 解码引擎路由分发 (Decoder Router)         │
│  ├── WMF/EMF  ──────> GDI EnhMetaFile API (0 增加体积)         │
│  ├── HEIC/HEIF ──────> Windows WIC COM Interface (0 增加体积)   │
│  ├── CUR/ANI   ──────> Win32 Icon API / RIFF 复用 (0 增加体积)     │
│  ├── TGA        ──────> 纯 C 原生 Header + RLE 解析 (< 2KB)        │
│  ├── APNG       ──────> 纯 C Chunk 解析器 + 帧提取 (< 5KB)         │
│  └── AVIF       ──────> libavif 静态编译库 (~400KB)             │
├─────────────────────────────────────────────────────────────────┤
│                      3. 统一图像容器 (Image Container)            │
│  - 静态图: 转换/生成标准 32-bit ARGB HBITMAP / DIB Section        │
│  - 动图 (APNG/ANI): 构建统一 viv_anim_frame_t 链表与帧延时数组   │
├─────────────────────────────────────────────────────────────────┤
│                      4. 渲染与渲染器混合 (Render Pipeline)         │
│  - 静态图统一进入 GDI BitBlt/AlphaBlend 缩放渲染管线            │
│  - 动图统一接入 viv_animation_timer_proc 定时器进行帧交叠刷新    │
└─────────────────────────────────────────────────────────────────┘
```

## 二、 6 大扩展格式深度分析与实施方案

### 1. APNG (Animated PNG) —— 高清透明动图
* **定位与场景**: 替代传统 256 色 GIF 的真彩色无损透明动图。
* **实现技术**: 
  * 扩展 PNG 文件头检测逻辑，检索 `acTL` (Animation Control Chunk) 块。
  * 提取 `fcTL` (Frame Control Chunk) 获取帧宽高、偏移量 (`x_offset`, `y_offset`) 及帧延迟 (`delay_num / delay_den`)。
  * 提取 `fdAT` 并拼装为标准 PNG 帧通过 GDI+/libpng 进行局部解码，按 Dispose/Blend 模式（`APNG_DISPOSE_OP_*`, `APNG_BLEND_OP_*`）混合至全尺寸 ARGB 帧缓冲区。
* **文件修改**: `src/viv.c`, `src/apng.c` (新设), `src/apng.h` (新设)。
* **资源开销**: 体积 +3KB，内存按帧尺寸分配，CPU 仅在帧切换瞬间运算。

### 2. TGA (Targa Bitmaps) —— 游戏与 CG 无损贴图
* **定位与场景**: 3D 游戏 MOD、二次元渲染素材、无损纯色贴图。
* **实现技术**:
  * 纯 C 语言读取 18 字节 TGA Header，解析图像类型（Uncompressed / RLE Encrypted RGB/RGBA）。
  * 原生 C 实现 RLE 游程编码解压缩循环，输出为 32 位 BGR/BGRA 字节流。
  * 垂直翻转标志位处理（TGA 默认从左下角存储，需根据 Descriptor Byte 自动倒序行索引）。
* **文件修改**: `src/viv.c`, `src/tga.c` (新设), `src/tga.h` (新设)。
* **资源开销**: 体积 +2KB，零第三方依赖，解码速度高于 JPG/PNG。

### 3. WMF / EMF (Windows Metafile / Enhanced Metafile) —— 矢量图元文件
* **定位与场景**: Windows Office 剪贴画、矢量插图、排版图。
* **实现技术**:
  * 零第三方库依赖，调用 Win32 原生 GDI API。
  * 使用 `GetEnhMetaFileW` 或 `SetWinMetaFileBits` 将内存/文件加载为 `HENHMETAFILE` 句柄。
  * 获取 Metafile Header 的 Bound 矩形尺寸，创建与画面尺寸一致的 32-bit 内存 DIB HDC，调用 `PlayEnhMetaFile` 矢量渲染至位图。
* **文件修改**: `src/viv.c` (直接内联 GDI 解码逻辑)。
* **资源开销**: 体积 +1KB，0 运行与内存负担。

### 4. CUR / ANI (Windows 鼠标指针与动态光标) —— 桌面资源与动图扩展
* **定位与场景**: Windows 桌面主题光标、美化资源。
* **实现技术**:
  * `.cur` 扩展名复用现有 `ico.c` 解码路径，额外读取 2 字节 Hotspot (X/Y) 偏置信息。
  * `.ani` 解析 RIFF 文件格式头，定位 `anih` (Header 提取帧数与默认 rate) 和 `LIST 'fram'` (提取内部包含了多个 ICON/CUR 块的数据链)。
  * 将组装出的 CUR 帧转换为 `viv_animation_t` 序列。
* **文件修改**: `src/viv.c`, `src/ani.c` (新设)。
* **资源开销**: 体积 +3KB，内存消耗按 32x32~128x128 像素微量分配。

### 5. HEIC / HEIF (High Efficiency Image Format) —— 移动端/iPhone 传图
* **定位与场景**: 双击查看手机传输到 PC 的 `.heic` 照片。
* **实现技术**:
  * 使用 Windows WIC (Windows Imaging Component) COM 接口。
  * 调用 `IWICImagingFactory::CreateDecoderFromFilename` / `CreateDecoderFromStream`。
  * 匹配 CLSID 为 `GUID_ContainerFormatHeif` 的解码器。系统若安装有 HEVC 扩展将自动透传并激活硬件显卡解码。
* **文件修改**: `src/viv.c`, `src/wic_decoder.c` (新设)。
* **资源开销**: 体积 +4KB（仅 COM 接口层包装），0 额外内存（由系统 WIC 框架管理）。

### 6. AVIF (AV1 Image Format) —— 现代 Web 图片与静态壁纸
* **定位与场景**: Edge/Chrome 保存的下一代超高压缩比静态及动图。
* **实现技术**:
  * 引入开源 `libavif` 静态 C 开发库（结合轻量后端 `dav1d`）。
  * 读入 Raw 文件内存数据调用 `avifDecoderReadMemory` 提取宽、高、色彩深度 (8/10/12 bit)。
  * 调用 `avifDecoderRGBImageAllocatePixels` 转换为 32-bit RGBA/ARGB DIB Section 指针。
* **文件修改**: `src/viv.c`, `src/avif_decoder.c` (新设), 引入外部构建脚本依赖。
* **资源开销**: 体积 +350KB ~ 500KB，解压瞬间 CPU 微量开销，位图就绪后恢复正常。

```c
HBITMAP viv_decode_wmf_emf(const BYTE *data, SIZE_T size, int *out_w, int *out_h) {
    HENHMETAFILE hemf = SetEnhMetaFileBits((UINT)size, data);
    if (!hemf) {
        hemf = GetEnhMetaFileW(...);
    }
    if (!hemf) return NULL;

    ENHMETAHEADER hdr;
    GetEnhMetaFileHeader(hemf, sizeof(hdr), &hdr);
    int w = hdr.rclBounds.right - hdr.rclBounds.left;
    int h = hdr.rclBounds.bottom - hdr.rclBounds.top;

    // 创建 GDI 兼容 DC 与 DIBSection
    HDC hdc_mem = CreateCompatibleDC(NULL);
    HBITMAP hbmp = viv_create_32bit_hbitmap(hdc_mem, w, h);
    SelectObject(hdc_mem, hbmp);
    RECT rect = { 0, 0, w, h };
    PlayEnhMetaFile(hdc_mem, hemf, &rect);

    DeleteDC(hdc_mem);
    DeleteEnhMetaFile(hemf);
    *out_w = w; *out_h = h;
    return hbmp;
}
```

## 四、 质量验证与测试标准

1. **零崩溃边界测试**：构造损坏/截断的 0 字节文件，测试各新格式解码器的 Exit 保护逻辑，确保不发生 Safe Size 算术溢出与野指针访问。
2. **轻量化指标验证**：
   - 最终编译 Exe 目标体积增加值必须 **< 500 KB**。
   - 静态图解压后无持续后台线程运行，空闲 CPU 占用 **0%**。
   - 动图（APNG / ANI）播放时 CPU 占用 **< 2%**。
3. **像素防错位与透明通道测试**：
   - 针对 32 位带有 Alpha 通道的 APNG/TGA/CUR/AVIF，确保背景 AlphaBlend 混合无黑边/白边渲染错乱。
