# voidImageViewer 自动更新设计（2026-11-03）

## 目标与边界

在“关于”窗口底部“项目地址”右侧增加“更新”按钮。正常启动主窗口后在后台检查一次；发现稳定新版时提示。用户确认后自动下载、校验、关闭、替换并重启。

这是用户明确选择的“自动下载安装包并替换当前版本”，不是打开浏览器让用户手动下载。保留现有看图、配置、多语言、快捷键和文件关联行为；不顺带重构图像模块，不删除未经证实无用的目录，不使用 Git。

## 已核实的事实

- 公开仓库为 `https://github.com/HaiSeaman/voidImageViewer-i18n`。
- GitHub `releases/latest` 当前返回正式版 `3.6-i18n`，不是草稿或预发布版；附件有 x86/x64、中/英 NSIS 安装包和 SHA-256 digest。
- 当前没有 ZIP 附件。现有发布说明明确绿色版可直接替换 exe。
- 当前程序是原生 C / Win32，版本在 `src/version.h`，关于窗口在 `src/viv.c` 和 `res/voidImageViewer.rc`。
- 当前 NSIS 安装包支持 `/S`，但没有专用于升级的参数。直接静默运行会按默认选项重写配置位置、开始菜单和文件关联，不能作为安全升级。
- 安装版有同目录 `Uninstall.exe`，绿色版没有。以此识别当前运行方式；不把绿色版偷偷安装到 Program Files。
- 当前 v3.6 没有更新代码，旧安装包也不认识新升级参数，因此首个含更新功能的版本发布后，从下一版本起才能自动升级。不能宣称 v3.6 能原地获得本功能。

## 用户可见流程

1. 启动后主窗口照常显示，后台只查询一次正式最新版；网络失败静默，不影响看图。
2. “关于”中点击“更新”立即检查，按钮在检查期间显示“检查中”且不能重复启动任务。手动检查会明确报告“已是最新”、发现新版或失败原因。
3. 更新提示使用一个简洁的原生窗口：当前版本、新版本、文件大小，以及“将关闭本软件的所有窗口，保留个人设置”的说明。按钮为“立即更新”“稍后”。
4. 点击“立即更新”后在同一窗口显示真实下载字节进度和“取消”。下载完成并校验后才关闭程序；取消或失败不启动安装器，旧版不变。
5. 安装阶段不允许取消。安装版可能正常出现 Windows 管理员授权提示，拒绝授权则不替换。成功后重新打开原位置的新程序；失败保留/恢复旧版并重新打开，下一次启动显示可理解的失败提示。
6. 启动检查只提示，不未经确认下载或替换。手动和启动检查共用同一任务与提示窗口，避免重复弹窗。

## 检查与附件选择

- 使用 Windows 自带 WinHTTP，以 HTTPS 访问固定地址 `https://api.github.com/repos/HaiSeaman/voidImageViewer-i18n/releases/latest`，不引入 curl、PowerShell、浏览器或第三方更新框架。
- 请求带固定 User-Agent 和 `Accept: application/vnd.github+json`。限制响应大小、设置连接/接收超时、校验 HTTP 200 和 JSON 结构。
- 只接受 `draft=false`、`prerelease=false`。从 `tag_name` 开头解析 `主版本.次版本[.修订[.构建]]`，允许已使用的 `-i18n` 后缀；只有数值版本更高才提示。不规则版本不猜测、不降级。
- 使用编译时的 x86/x64 和当前中/英界面语言，精确匹配：`voidImageViewer-<数值版本>.<架构>.<zh-CN|en-US>-Setup.exe`。不把无位数标识的附件当成更新包。
- 附件必须具有 GitHub API 返回的 `sha256:` digest、正数大小、固定 GitHub 下载地址。用流式 SHA-256 和实际字节数同时校验；Windows 7 及以上使用系统 BCrypt。
- 下载到当前用户本地临时更新目录，先写 `.part`，完成后校验再改名。HTTPS 重定向不得降级为 HTTP；只执行 API 中固定仓库下载地址对应的安装包。下载体积设置合理上限，失败清理残缺文件。

## 替换机制（不新增常驻服务）

- 新增独立更新模块负责网络、版本比较、SHA-256、任务状态和进度消息，避免继续膨胀 `viv.c`。
- 开始替换时，把当前 exe 复制到更新临时目录，以隐藏的内部参数启动这个临时副本作为“一次性更新助手”，然后正常关闭主程序。不是常驻服务，不依赖 cmd/PowerShell 脚本。
- 更新助手按进程 ID 等待当前程序真正退出；只向同一 exe 路径的其他实例发送正常关闭消息，并设置有限等待时间，不能误关别的软件或无限等待。
- 随后启动已校验的 NSIS 包，显式传原安装目录，等待安装结果。安装版使用 `/S /UPDATE /D=<原目录>`；绿色版使用 `/S /PORTABLE /D=<原目录>`。安装版需要权限时通过 Windows 正常 UAC 授权，不绕过权限。
- 安装结束后读取目标 exe 的文件版本，必须等于刚下载的版本才报告成功并重启。失败时绿色版从同目录备份恢复旧 exe；安装版尚未改动或安装器报告失败则重启旧程序，绝不把失败当成功。
- 助手写入一个不含隐私的小型结果文件，重启后的程序用现有本地化机制提示成功或失败。更新临时文件可清理，不能删除配置、图片或整个安装目录。

## NSIS 必须增加的专用模式

- `/UPDATE`：只覆盖原目录的程序与卸载器，不读取默认安装选项来重置配置、开始菜单或文件关联；沿用原目录，保留现有 ini。传播复制/执行错误为非零退出码。
- `/PORTABLE`：只把新 exe 覆盖到显式原目录；不写卸载器、注册表、开始菜单、文件关联或 AppData 配置。
- 普通手动安装维持现有交互与选项。
- 两种内部参数必须要求 `/S` 和显式 `/D`，以防误用时装到默认目录。/D 为 NSIS 规则放在命令行最后，路径即使含空格也不加引号。
- 发布规则不变：每个版本提供 x86/x64 中英安装包及 GitHub digest；无需为更新新增 ZIP 或解压依赖。下一版开始，新安装包同时支持安装版和绿色版升级。

## 界面与多语言

- 关于窗口底部顺序为“项目地址”“更新”“确定”“取消”，必要时等宽调整按钮，不覆盖文字。
- 新增更新提示/进度窗口及所需控件 ID，沿用项目原生 Win32 对话框风格；不另外制作网页界面。
- 所有新增用户可见文本补齐现有 10 种语言，并继续把本地化 ID 追加在数组末尾，防止位置错配。
- 后台线程绝不直接操作窗口；通过消息把结果交给界面线程。对话框销毁后不能访问失效句柄，程序退出时取消/等待任务并释放网络、线程和文件资源。

## 验证（只做无界面命令行验证）

1. 纯逻辑单元测试：合法/非法/草稿/预发布/字段缺失 JSON、3.6-i18n 与数值版本比较、x86/x64 与语言附件选择、digest 和大小验证、重定向及超长响应限制。
2. 下载集成测试：真实读取 GitHub 当前 release，验证解析和 SHA-256 对照；不把任何测试 release 安装到主机。
3. 在临时测试目录模拟绿色版升级：旧 exe、保留 ini、模拟新版本、程序占用退出、替换成功、失败恢复、路径含空格与中文。
4. NSIS 脚本编译验证 `/UPDATE`、`/PORTABLE` 的参数和错误退出路径；不执行会更改主机的安装包，不测试 GUI/UAC。
5. 运行项目已有 `tests\build_and_run_test.bat`，并分别编译 x64/Win32 Release；如实记录未覆盖的真实 GUI、UAC 和线上新版本升级测试。

## 不做的事

不静默绕过 UAC，不强制自动安装，不收集数据，不添加常驻进程，不更新预发布版，不降级，不猜附件，不删除用户文件，不顺手清理第三方库或重构图像代码。源码模块、优化点、死代码与无用目录另列审计结果，明确区分“证实可删”和“需进一步确认”。
