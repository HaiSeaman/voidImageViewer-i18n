# RELEASE NOTES — voidImageViewer-i18n 3.4

发布日期：2026-09-16
上一版本：3.3（2026-09-06）

## 一句话版本

修复无边框叠层在拖动图片时的残影错位，修复自 0.0.0.1b 起就失效的中键拖动滚动，右键菜单底部以【关于】替代【帮助】子菜单，关于对话框新增【项目地址】按钮直达 GitHub 仓库，并完成一次全库翻译完整性与代码洁净度审计。

## 新增

- **右键菜单精简**：菜单栏的【帮助】子菜单不再整体挂到右键菜单底部，原位置改为单个【关于】项（按内容识别子菜单，不依赖位置；文案自动剥离键盘助记符，避免与【动画(A)】的字母冲突）。菜单栏本体（选项中开启时）的【帮助】不受影响。
- **关于对话框【项目地址】按钮**：底部栏最左侧（确定/取消仍在右侧），点击用系统默认浏览器打开本仓库页面 `https://github.com/HaiSeaman/voidImageViewer-i18n`；按钮文案与 URL 为两个新的本地化 id，已同步到全部 10 张语言表末尾。
- **开发者文档更新**：`docs/RELEASE-NOTES-3.4.md`（本文件）与 00/01/02/03 四份开发者文档同步本次全部变更。
- **端到端回归测试 ×3**（`tests/`）：
  - `e2e_overlay_scroll_test.ps1` —— 纯黑图 + 滚轮放大 + SendInput 拖动，统计标题条以下亮像素捕捉叠层残影，并验证关闭按钮悬停反馈；
  - `e2e_scroll_modes_test.ps1` —— 棋盘图采样像素差分验证中键拖动滚动、角标图验证 1:1 滚动松开不回跳；
  - `e2e_ui_menu_test.ps1` —— 截图右键菜单与关于对话框，并以 WM_COMMAND 驱动【项目地址】按钮验证浏览器真实打开仓库页。

## 修复

- **拖动残影（本版核心修复）**：无边框模式下，左上角文件名与右上角最小化/最大化/关闭按钮绘制在客户区顶部条带内，而平移图片使用 `ScrollWindowEx` 滚动整个客户区，每一步都把叠层像素连同图片一起搬走，仅新露出的窄条被重绘——表现为文件名沿拖动方向拖尾、按钮出现重影错位。现在叠层可见时把滚动范围限制在条带以下，并对条带整体失效重绘（其下图片内容同步重画）；全屏（无叠层）保持原有快速路径。
- **按钮裁剪**：自绘按钮绘制前曾用 `SelectClipRgn(hdc, NULL)` 清掉 WM_PAINT 更新区裁剪，导致每次局部重绘都全量重画按钮、可画到失效区域之外。现改为在现有裁剪上做交集。
- **中键拖动滚动从未生效**：0.0.0.1b 引入的"中键移动"每次只把光标拉回锚点、位移被丢弃。现按光标位移调用视图滚动（与左键拖动同方向），随后再把光标拉回锚点，保留"无限行程"手感。
- **拖动中丢失鼠标捕获**：拖动时被其他窗口抢走捕获（如 Alt+Tab）后不会再收到按键释放消息，中键拖动会持续把光标钉回旧锚点。`WM_CAPTURECHANGED` 现在结束拖动状态（并清除按钮按下/悬停态）。
- **仓库卫生**：恢复 10 张语言表被脚本剥掉的 UTF-8 BOM；删除仓库根残留的 `test_left_drag.obj`、`test_playlist_delete.obj`。

## 审计结论（3.4 发布前全库体检）

- 本地化：10 张语言表 × 263 条与 id 枚举逐位对齐；0 个未被引用的 id；0 个 printf 占位符跨语言不一致；无未翻译条目（注意：日语汉字与中文共享 CJK 码位，脚本按区段检测会误报，已逐条人工复核）。
- 代码洁净度：static 死函数 0；工程文件与磁盘一致；链接库均有实际调用；无可删的重复实现。
- 选项对话框组合框：左键 0–6、右键 0–2、滚轮 0–2 的填充顺序与配置值一一对应，逐项核对无误。

## 回归验证

- x64 与 Win32 Release 均 /W3 0 警告。
- 单元测试：left_drag 16/16、playlist_delete 3/3（含 --show-bug 预期失败）。
- 端到端：叠层测试对 3.3 旧版报 1006+49 个残影像素、3.4 为 0；中键拖动像素差分 0 → 15729；UI 菜单测试确认弹窗底部为【关于】、【项目地址】按钮真实打开浏览器。

## 升级说明

- 便携版：直接替换 `voidImageViewer.exe`（配置 ini 兼容，无新增配置项）。
- 安装版：NSIS 安装包沿读旧配置升级安装。
- 语言：新增字符串已进入全部 10 种语言；界面文案无需任何用户操作。
