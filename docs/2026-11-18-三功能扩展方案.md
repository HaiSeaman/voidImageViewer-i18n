# 三项功能扩展方案（评审稿）

> 日期：2026-11-18  
> 状态：**仅设计，未修改任何代码**  
> 范围：最近打开 / 收藏夹、当前列表按名称筛选、图片信息面板（EXIF 全套）  
> 目标版本：v3.7（暂定）

---

## 0. 结论摘要

三个功能都属于"看图周边增强"，**不需要改动图片解码和渲染核心**，风险整体可控。

推荐实施顺序：

1. **最近打开 / 收藏夹**：只碰配置与菜单，风险最低，先做它可以验证新的动态菜单机制。
2. **当前列表按名称筛选**：会碰导航核心 `_viv_next` / `_viv_home`，必须重点测试。
3. **图片信息面板**：UI 与 EXIF 读取工作量最大，放最后。

最大的三个技术风险：

| 风险 | 位置 | 说明 |
|---|---|---|
| 语言表"位置数组" | `localization.h` / 10 个语言表 | 新字符串只能追加到末尾，插中间会让所有文案错位且编译器不报错 |
| 导航核心 | `_viv_next` / `_viv_home` | 筛选要改这里；`_viv_home` 在"无匹配"时如果走到 `_viv_blank()` 会把播放列表清空 |
| EXIF 兼容性 | `os.c` / `heif.c` | 不同格式、不同 Windows 版本可读到的字段不一致，必须做"分层读取 + 读不到就诚实显示无数据" |

## 1. 边界：做什么，不做什么

### 1.1 做

- 最近打开：记录最近成功显示的图片路径，菜单里快速重开。
- 收藏夹：手动收藏当前图片，菜单里快速重开，可管理。
- 筛选：在当前播放列表/当前文件夹内按文件名子串过滤导航，不改变原列表内容。
- 图片信息：显示文件信息、图像信息、常用 EXIF、GPS；可复制全部信息。

### 1.2 不做（明确排除）

- 不做缩略图数据库、标签、评分、云同步、多标签页。
- 不复制图片文件，最近/收藏只存路径。
- 不写 EXIF，不做元数据编辑。
- 不联网打开地图；GPS 只显示和复制坐标。
- 不引入新的第三方库（继续纯 C + Win32 + 现有 libwebp/libheif）。
- 不解析厂商私有 MakerNote（"EXIF 全套"指常用 EXIF + GPS + 文件/图像信息，不是每个厂商的私有字段）。

### 2.2 三条硬约束

1. **语言表只能追加**  
   `localization_id_t` 是按枚举顺序取数组下标。新增字符串必须追加到枚举末尾，并同步追加到 **全部 10 张语言表的末尾**。插中间不会编译报错，但所有文案会错位。

2. **动态菜单项不能直接塞进静态命令表**  
   `_viv_commands[]` 是静态数组，最近打开/收藏夹的条目是运行时变化的。必须给动态项单独预留命令 ID 区间，并在 `_viv_command_with_is_key_repeat` 里先处理这个区间。

3. **播放列表节点不能被长期缓存**  
   删除、重命名、清空、切换文件夹都会让 `_viv_playlist_t` 节点失效。最近/收藏只存**路径字符串**；信息面板每次刷新只复制当前路径，不保存节点指针。

## 3. 功能一：最近打开 / 收藏夹

### 3.1 使用体验

- 文件菜单新增两个子菜单：**最近打开**、**收藏夹**。
- 最近打开：自动记录最近成功显示的图片，最多 20 条，最新的在最上面。
- 收藏夹：手动添加/移除当前图片，最多 100 条。
- 点条目：打开该图片；如果文件已不存在，给出提示。
- 右键菜单会自动继承文件子菜单里的这两项（因为右键菜单挂载了完整主菜单树）。
- 收藏夹提供"管理收藏夹"对话框，可打开、移除、清空。

### 3.2 菜单与对话框 UI

```
文件
  打开文件...                    Ctrl+O
  打开文件夹...                  Ctrl+B
  ─────────────────────────
  最近打开                 ▸
      1. DSC_1234.JPG  (2026-11)
      2. cover.png     (桌面)
      ─────────────
      清除最近记录
  收藏夹                   ▸
      1. wallpaper.webp (下载)
      ─────────────
      添加当前图片到收藏夹
      管理收藏夹...
  ─────────────────────────
  打开文件位置...              Ctrl+Enter
  ...
```

```
┌─ 管理收藏夹 ─────────────────────────────┐
│ ┌──────────────────────────────────────┐ │
│ │ C:\Photos\2026\DSC_1234.JPG          │ │
│ │ C:\Users\xi\Desktop\cover.png        │ │
│ │ D:\Pictures\wallpaper.webp           │ │
│ └──────────────────────────────────────┘ │
│                                          │
│ [打开]  [移除]  [清空]        [关闭]      │
└──────────────────────────────────────────┘
```

UI 细节：

- 菜单条目显示格式：`序号. 文件名  (父文件夹名)`。文件名太长时截断并加省略号。
- 菜单文本里的 `&` 必须转义成 `&&`，否则文件名会被菜单当成助记符。
- 最近列表为空时显示一条灰色"（空）"，不显示空白子菜单。
- 收藏夹管理对话框沿用现有 `IDD_JUMPTO` 的风格：ListBox + 按钮，模态，居中。
- 对话框按钮文本全部走语言表注入，不在 rc 里写死。

### 3.3 存储设计

继续使用单文件 `voidImageViewer.ini`，不新增配置文件。

| 键 | 说明 |
|---|---|
| `recent_count` | 最近条数（0-20） |
| `recent_0` ... `recent_19` | 最近路径，0 为最新 |
| `favorite_count` | 收藏条数（0-100） |
| `favorite_0` ... `favorite_99` | 收藏路径，按添加顺序 |

规则：

- 路径去重用 `CompareStringOrdinal(..., TRUE)`（忽略大小写、与区域无关）。
- 最近加入时：如果已存在，先删掉旧位置，再插到最前面；超过 20 条删掉最旧的。
- 收藏加入时：已存在则不重复；超过 100 条给出提示并拒绝（或删最旧，二选一，建议拒绝并提示，避免误删收藏）。
- 路径长度上限 `STRING_SIZE`（1024 wchar）。超长路径不记录，避免截断后指向错误文件。
- ini 解析器只在第一个 `=` 处分割，路径里含 `=` 是安全的；Windows 文件名不允许换行，因此也不会破坏行格式。

保存时机：

- 收藏夹每次增删立即保存（操作不频繁，保证崩溃也不丢）。
- 最近打开只在内存里更新，退出时随 `config_save_settings` 一起保存。  
  这样避免每翻一张图就重写整个 ini；代价是程序崩溃会丢最近的几条记录，可以接受。

**AppData 逻辑陷阱（必须处理）**：

现有加载顺序是先读 exe 同目录 ini，再读 `%APPDATA%` ini。  
如果 `appdata=1`，根 ini 只应保存 `appdata` 一个键，但旧逻辑仍会把根 ini 的其他键读进来。  
新增路径列表时必须：

1. 在根 ini 读取时先读 `appdata`；
2. 当 `is_root && config_appdata` 时，**跳过**路径列表加载；
3. 只从真正的当前配置文件加载路径列表。

否则会出现"AppData 里的配置没有最近记录，却把 exe 目录的旧记录读进来"的脏数据。

记录时机：

- 在 `_viv_start_first_frame()` 末尾记录当前 `_viv_frame_fd->cFileName`。
- 只在文件非空、非"文件未找到"、非"加载失败"时记录。
- 预加载不会走到这里，只有真正显示时才记录，所以不会把后台预载的图片记进最近列表。
- 刷新当前图会再次记录，但因为去重并移动到最前，效果无害。

菜单动态填充：

- 在 `_viv_commands[]` 文件菜单中新增两个 `MF_POPUP` 项："最近打开"、"收藏夹"。
- 在 `_viv_create_menu()` 里创建这两个弹出菜单后，把句柄存到全局变量，并立刻填充一次。
- 在 `WM_INITMENUPOPUP` 中判断 `wParam` 是否是这两个子菜单，是就重新填充，保证打开菜单前数据最新。
- 动态条目使用独立 ID 区间，命令分发函数开头先判断区间，再走原有 switch。

### 3.5 逻辑问题与对策

| 问题 | 后果 | 对策 |
|---|---|---|
| 语言表插错位置 | 全菜单文案错位 | 只追加到末尾；加 Debug 下逐语言、逐 ID 的 NULL 检查 |
| 动态菜单 ID 冲突 | 点最近条目却执行别的命令 | 预留独立区间；命令分发先判断区间 |
| 文件名含 `&` | 菜单显示异常/助记符冲突 | 动态文本统一 `&` -> `&&` |
| 右键菜单共享子菜单被递归销毁 | 崩溃/菜单消失 | 沿用现有"先 RemoveMenu 再 DestroyMenu"逻辑；动态子菜单只挂在共享子菜单内部，不单独销毁 |
| AppData 根 ini 旧记录串入 | 最近/收藏出现脏数据 | 按 3.3 的加载顺序修正 |
| 预加载被记入最近 | 最近列表出现没看过的图 | 只在 `_viv_start_first_frame` 记录 |
| 文件被删除 | 点开失败 | 最近：提示并自动移除；收藏：保留并提示，方便移动硬盘重新接入 |
| 多实例同时写 ini | 后退出者覆盖前者 | 现有原子替换已降低损坏风险；路径列表以最后退出者为准，可接受 |
| 菜单过长 | 屏幕放不下 | 最近 20、收藏 100；Windows 菜单本身可滚动 |

### 3.6 验收标准

- 打开 25 张图后，最近列表只保留最新 20 张，顺序正确。
- 同一路径重复打开不会产生重复条目，只会移到最前。
- 中文、空格、`&`、`=`、长路径文件名显示和打开都正常。
- 收藏/取消收藏后，菜单状态立即正确；重启后仍保留。
- 收藏夹管理对话框可打开、移除、清空；清空后菜单显示"（空）"。
- 删除一个最近文件后点击它，提示"文件未找到"，并且该条从最近列表消失。
- 切换语言后，两个子菜单标题和固定条目文本立即更新。
- AppData 模式与便携模式各测一遍，记录不会串目录。

## 4. 功能二：当前列表按名称筛选

### 4.1 使用体验

- 快捷键 `Alt+F` 打开/关闭顶部浮动筛选条（不与现有快捷键冲突）。
- 输入即筛选，匹配当前播放列表或当前文件夹中的文件名子串，忽略大小写。
- 输入里包含 `\`、`/`、`:` 时，按完整路径匹配（沿用现有"跳到"对话框的规则）。
- 筛选条显示"匹配 N / 总数"。
- `Enter`：跳到下一个匹配；`Shift+Enter`：跳到上一个匹配。
- `Esc`：清空筛选并关闭筛选条。
- 筛选只影响"上一张/下一张/第一个/最后一个/预加载"的候选范围，**不删除、不重排播放列表**。
- 当前图片即使不匹配筛选也继续显示，不会突然黑屏。
- Everything 随机模式下筛选不可用，给出提示（随机结果不是固定列表，筛选没有意义）。

### 4.2 筛选条 UI

推荐做成一个**无标题栏的浮动小对话框**，而不是主窗口的子控件。

```
┌──────────────────────────────────────────────┐
│ 筛选: [ sunset                    ] 12/350 [×] │
└──────────────────────────────────────────────┘
```

为什么用浮动对话框：

- 主窗口是无边框自绘窗口，顶部横条还兼任拖动/最大化命中区域；直接往里塞子控件会破坏命中测试和绘制逻辑。
- 浮动对话框是独立窗口，不参与主窗口布局，风险最小。
- 现有 `IDD_JUMPTO` 已经证明这种小对话框模式可行。

UI 细节：

- 样式：`WS_POPUP | WS_BORDER`，`WS_EX_TOOLWINDOW`（不占任务栏），owner 为主窗口。
- 位置：主窗口顶部居中，距顶约 8 像素（按 DPI 缩放）。
- 主窗口移动、缩放、进出全屏时重新定位。
- 控件：`EDIT`（单行、自动水平滚动）、`STATIC`（计数）、`BUTTON`（× 清除关闭）。
- 打开时自动 `SetFocus` 到输入框。
- 点击图片区域后焦点回主窗口，筛选条保持显示、筛选保持生效。
- `hover_show_ui` 自动隐藏 UI 的逻辑不影响这个用户主动打开的筛选条。

### 4.3 筛选与导航逻辑

核心是一个谓词函数：

```c
static int _viv_filter_match(const WIN32_FIND_DATA *fd);
```

规则：

- 筛选未激活：永远返回 1。
- 激活：取文件名（或完整路径），用 `StrStrI` 做忽略大小写子串匹配。
- 空字符串：视为未激活。

需要修改的位置：

1. `_viv_next` 的非随机分支
   - 遍历播放列表时：不匹配的节点直接跳过，不参与 `best_fd` / `start_fd` 比较。
   - 无播放列表、现场扫描文件夹时：`_viv_is_valid_filename` 之后再加筛选判断。
   - 洗牌分支：从当前洗牌下标开始，按方向逐项前进，最多绕一圈，找到第一个匹配项。
2. `_viv_home`
   - 播放列表：找最小/最大时只考虑匹配项。
   - 洗牌：从头部/尾部开始找第一个匹配项。
   - 无播放列表扫描文件夹：同样加筛选判断。
3. `_viv_preload_next`
   - 它内部调用 `_viv_next(..., is_preload=1, ...)`，只要 `_viv_next` 改好，预加载自动只预载匹配项。
4. 计数
   - 单独函数遍历当前列表/文件夹，统计匹配数。
   - 输入变化后不要每敲一个字立刻全量统计；用 150-250ms 的防抖定时器，避免大列表卡顿。

**最关键的坑：`_viv_home` 在没有任何候选时会调用 `_viv_blank()`。**  
`_viv_blank()` 会 `_viv_playlist_clearall()`，如果筛选结果为 0 还走这条路，播放列表会被清空。  
必须在筛选激活且无匹配时拦截：只更新状态提示，不调用 `_viv_blank()`。

### 4.5 逻辑问题与对策

| 问题 | 后果 | 对策 |
|---|---|---|
| `_viv_home` 无匹配走 `_viv_blank()` | 播放列表被清空 | 筛选激活时拦截，不 blank |
| 洗牌分支死循环 | 无匹配时卡死 | 最多扫描 `_viv_playlist_count` 次后放弃 |
| `_viv_next` 的 `got_start` 没过滤 | 无下一张时跳到不匹配的图 | `start_fd` 更新也必须判断筛选 |
| 当前图不匹配 | 用户以为筛选失效 | 筛选条显示"当前图片不在筛选结果中"，不自动跳图 |
| 手动打开新文件/文件夹 | 旧筛选把新列表过滤掉，看起来像"没打开" | 手动打开文件、打开文件夹、拖放、命令行加载时自动清空筛选 |
| 删除/重命名当前图 | 当前节点失效 | 不缓存节点/数组；删除后由 `_viv_next` 按实时链表重新找下一个匹配 |
| 预加载加载了不匹配的图 | 翻页时出现意外图片 | `_viv_next` 过滤后预加载自然只选匹配项 |
| 大列表每敲一个字全量匹配 | 输入卡顿 | 150-250ms 防抖 + 计数延后 |
| 随机 Everything 模式 | 没有固定列表可筛 | 禁用筛选并提示 |
| 全屏时浮动条不显示 | 无法筛选 | owner 设为主窗口，全屏时 `SetWindowPos(HWND_TOP)`；实测确认 |
| 阿拉伯语 RTL | 输入框/布局方向异常 | 对话框加 `WS_EX_LAYOUTRTL`，文本方向按系统处理 |

### 4.6 验收标准

- 打开一个 100 张图的文件夹，输入关键字，计数正确，`Enter` 能逐个跳转。

- 筛选 + 随机播放：只在匹配项中随机。
- 筛选 + 预加载：下一张匹配项能秒开。

- 筛选状态下重命名当前图，列表和匹配结果同步更新，不崩溃。
- 打开新文件夹后筛选自动清空。
- 切换语言、RTL、DPI 125%/150% 下布局正常。
- 大文件夹（1 万张以上）输入时不明显卡顿。

### 5.1 展示内容

分四组，读不到的字段直接不显示，不显示空行。

|---|

| 海拔（米） |

为什么用 ListView 而不是纯文本框：

- 两列天然对齐，中文/英文/数字混排不会参差不齐。
- 支持整行选择、键盘滚动、列宽随窗口调整。
- 分区行可以加粗（`NM_CUSTOMDRAW` 少量代码）或者只用 `【分组】` 文本，先保证功能。
- 复制功能自己实现：`Ctrl+C` / "复制全部" 按钮，把两列拼成 `名称: 值` 文本。

如果主人更看重"实现最简单"，可以退一步用**只读多行 EDIT**：  
一行一条 `名称: 值`，天然支持选择/复制/滚动，代码最少，但列不对齐、视觉上不如 ListView 专业。  
本方案推荐 ListView；如果主人要求"越简单越好"，再降级为 EDIT。

窗口行为：

- **无模态**（modeless）：打开后仍可用主窗口翻上一张/下一张，信息自动更新。
- 参考 IrfanView：它的 EXIF 窗口就是无模态，浏览其他图片时自动刷新，并且记住窗口大小/位置。
- owner 为主窗口，`WS_EX_TOOLWINDOW`，不占任务栏。
- `Esc` 或"关闭"销毁窗口；再次打开重新创建。
- 记住上次位置/大小，但**不在启动时自动打开**。
- 首次打开居中于主窗口；恢复位置时钳制在显示器工作区内，避免跑到屏幕外。
- 最小尺寸约 360 x 320（按 DPI 缩放）。
- 支持 RTL；阿拉伯语时加 `WS_EX_LAYOUTRTL`，并检查两列顺序。
- 字体用系统默认 UI 字体；列宽按 `os_logical_wide` 缩放。

自动刷新时机：

- 打开窗口时刷新。
- 主窗口显示新图片时（`_viv_start_first_frame` 末尾）刷新。
- 切换语言时刷新标签文本。
- 帧动画换帧不刷新整个面板（避免频繁读文件）；只更新"当前帧"一行即可，或者干脆不更新。

### 5.3 EXIF 数据来源：分层读取

不同格式、不同 Windows 版本能读到的元数据不一样，必须分层：

#### 第一层：Windows 属性系统（首选）

现有 `os_get_orientation` 已经证明可行：`SHGetPropertyStoreFromIDList` + `IPropertyStore::GetValue`。  
扩展成 `os_read_image_metadata(const wchar_t *filename, os_image_metadata_t *out)`，读取 `propkey.h` 里的 `PKEY_*` 常量：

- 相机：`PKEY_Photo_CameraManufacturer`、`PKEY_Photo_CameraModel`、`PKEY_Photo_LensModel`
- 拍摄：`PKEY_Photo_DateTaken`、`PKEY_Photo_ExposureTime`、`PKEY_Photo_FNumber`、`PKEY_Photo_ISOSpeed`、`PKEY_Photo_FocalLength`、`PKEY_Photo_FocalLengthInFilm`、`PKEY_Photo_ExposureBias`、`PKEY_Photo_Flash`、`PKEY_Photo_MeteringMode`、`PKEY_Photo_WhiteBalance`、`PKEY_Photo_ExposureProgram`
- 图像：`PKEY_Image_HorizontalResolution`、`PKEY_Image_VerticalResolution`、`PKEY_Image_BitDepth`、`PKEY_Image_Dimensions`
- 描述：`PKEY_Image_ImageDescription`、`PKEY_Photo_ExifVersion`、`PKEY_Photo_ColorSpace`、`PKEY_Comment`、`PKEY_Photo_Copyright`、`PKEY_Photo_Artist`
- GPS：`PKEY_GPS_Latitude`、`PKEY_GPS_Longitude`、`PKEY_GPS_Altitude`、`PKEY_GPS_LatitudeRef`、`PKEY_GPS_LongitudeRef`、`PKEY_GPS_AltitudeRef`、`PKEY_GPS_ImgDirection`、`PKEY_GPS_Date`、`PKEY_GPS_Time`

值类型要分别处理：

| `PROPVARIANT.vt` | 处理 |
|---|---|
| `VT_LPWSTR` / `VT_BSTR` | 直接复制字符串 |
| `VT_UI2` / `VT_UI4` / `VT_UI8` | 转整数 |
| `VT_R8` / `VT_R4` | 转浮点，格式化 |
| `VT_FILETIME` | 转本地时间再格式化 |
| `VT_DATE` | 转系统时间再格式化 |
| `VT_VECTOR | VT_R8` | GPS 经纬度，按 度/分/秒 格式化 |
| `VT_BOOL` | 是/否 |
| `VT_EMPTY` / 其他 | 跳过该字段 |

注意：`PKEY_*` 的 `formatID + pid` 可以手写，也可以直接在 `os.c` 里 `#include <propkey.h>`。  
工程当前 `_WIN32_WINNT` 是 0x0501，但 `propkey.h` 的常量在 Vista+ 可用；如果旧 SDK 编译报错，就用文档里的 GUID+PID 手写表，保持和现有 `_os_FMTID_ImageProperties` 一样的风格。

#### 第二层：GDI+ 属性回退（JPEG/TIFF）

如果属性系统读不到（例如某些 Win7 环境或特殊文件），用 GDI+：

- 已有 `GdipGetPropertyItemSize`、`GdipGetPropertyItem` 动态导入。
- 需要补一个 `GdipGetPropertyIdList`。
- 读 `PropertyTagEquipMake`、`PropertyTagEquipModel`、`PropertyTagExifExposureTime`、`PropertyTagExifFNumber`、`PropertyTagExifISOSpeed`、`PropertyTagExifDateTimeOriginal`、`PropertyTagExifFocalLength`、`PropertyTagExifFlash` 等常用 tag。
- 只做常用字段，不追求全量 tag；读不到就跳过。

#### 第三层：HEIC 内置解析（无系统 HEIF 扩展时）

`heif_get_orientation` 已经手工解析 HEIC 里的 EXIF TIFF 块。  
可以把它重构成一个通用的 EXIF TIFF 小解析器，返回常用 tag：

- IFD0：Make、Model、Software、DateTime、Artist、Copyright、ImageDescription、Orientation
- Exif SubIFD：ExposureTime、FNumber、ISO、DateTimeOriginal、FocalLength、Flash、ExposureBias、MeteringMode、WhiteBalance、ExposureProgram
- GPS IFD（可选）：经纬度、海拔

要求：所有偏移/长度都必须做边界检查，遇到畸形数据直接放弃，不能崩溃。

#### WebP / PNG 的说明

- WebP：Windows 属性系统不一定有 WebP 属性处理器；libwebp 的 demux 可以读 `EXIF` chunk，可作为后续增强。首版可以先只显示文件/图像信息，EXIF 显示"无数据"。
- PNG：Windows 10+ 对 `eXIf` chunk 有一定支持，Win7 基本没有；同样按"读到就显示，读不到就诚实提示"处理。

**诚实原则**：读不到就显示"该图片不包含 EXIF 信息"或"当前系统不支持读取该格式的 EXIF"，不要伪造、不要显示空白行。

### 5.5 逻辑问题与对策

| 问题 | 后果 | 对策 |
|---|---|---|
| 属性系统 COM 未初始化 | 读不到数据 | 窗口线程 `CoInitializeEx(COINIT_APARTMENTTHREADED)`，按返回值决定是否 `CoUninitialize` |
| 第三方属性处理器抛异常 | 崩溃 | 沿用 `os_get_orientation` 的 `__try/__except` 包裹 |
| `PROPVARIANT` 未清理 | 内存泄漏 | 每个字段读完 `PropVariantClear`，统一出口 |
| `VT_FILETIME` 时区 | 拍摄时间差 8 小时 | 明确 `FileTimeToLocalFileTime` 再显示，并用已知照片验证 |
| GPS 是向量不是字符串 | 格式化崩溃 | 只处理 `VT_VECTOR | VT_R8`，长度不足 3 就跳过 |
| 畸形 EXIF 偏移 | 越界读/崩溃 | 所有 TIFF 偏移、tag 数、数据长度都做边界检查 |
| 同步读元数据卡 UI | 网络/离线文件卡住 | 首版同步读取（本地文件通常很快）；若实测卡顿，再加短生命周期工作线程 + 代次号丢弃旧结果 |
| 信息窗口持有播放列表指针 | 删除/清空后悬空 | 只复制路径字符串，不保存节点指针 |
| 预加载触发刷新 | 信息面板显示预载图 | 只在 `_viv_start_first_frame` 刷新；预加载不调用它 |
| 切换语言 | 标签不更新 | `_viv_change_language` 里调用信息窗口的文本刷新 |
| 复制到剪贴板内存归属 | 泄漏/崩溃 | 按现有 `_viv_copy_filename` 的模式：`OpenClipboard` -> `GlobalAlloc` -> `SetClipboardData`，成功后不再释放 |
| 无 EXIF 的图 | 面板大片空白 | 显示一条本地化的"无 EXIF 数据"，并保留文件/图像信息 |
| RTL / 高 DPI | 列错位/文字截断 | `WS_EX_LAYOUTRTL`、列宽按 DPI 缩放、最小尺寸限制 |
| 窗口跑出屏幕 | 用户找不到 | 恢复位置时用 `MonitorFromWindow` + `GetMonitorInfo` 钳制 |

## 8. 实施顺序与风险控制

### 阶段 0：基础设施（无用户可见功能）

- 追加语言 ID 和占位字符串（先英文/中文，其他语言同步补）。
- 建立动态菜单 ID 区间和分发入口。
- 建立配置路径列表 API。
- 建立筛选匹配谓词（先不接 UI）。
- 编译 x86/x64 Debug/Release，确认无警告。

### 阶段 1：最近打开 / 收藏夹

- 配置读写、去重、上限。
- 菜单动态填充、管理对话框。
- 记录时机、缺失文件处理。
- 重点测 AppData/便携两种模式、菜单 `&` 转义、语言切换。

### 阶段 2：筛选

- 筛选条 UI、焦点/Esc/Enter。
- 修改 `_viv_next` / `_viv_home`，重点测"0 匹配不清空列表"。
- 测洗牌、预加载、删除、重命名、Everything 列表、大文件夹。

### 阶段 3：信息面板

- 先做文件/图像信息（不依赖 EXIF），把窗口和刷新跑通。
- 再接属性系统 EXIF。
- 再加 GDI+/HEIC 回退。
- 最后做 GPS、复制、RTL/DPI。

每个阶段结束都应能单独编译、单独验收，避免三个功能一起上导致问题难定位。

## 9. 测试与验证方案

### 9.1 编译

- 使用现有 `build_release_both.bat` 构建 x64 + x86 Release。
- 使用 Visual Studio 构建 Debug，开启调试堆检查。
- 不执行任何 GUI 自动化测试；界面部分由主人按验收清单手工确认。

### 9.2 逻辑测试（控制台，无界面）

建议新增三个小测试，沿用 `tests/build_and_run_test.bat` 的方式：

1. **路径列表测试** `tests/test_path_lists.c`
   - 添加、去重、移动到最前、超过上限淘汰。
   - 保存到临时 ini 再加载，内容一致。
   - 路径含中文、空格、`&`、`=`、1023 字符边界。
2. **筛选谓词测试** `tests/test_filter_match.c`
   - 空筛选、大小写、子串、完整路径模式、无匹配。
   - 文件名含中文、数字自然排序不受影响。
3. **EXIF 格式化测试** `tests/test_exif_format.c`
   - 曝光 1/500、f/2.8、ISO 400、焦距 35mm。
   - GPS 度分秒转换。
   - 缺失值、非法向量长度、`VT_EMPTY` 不崩溃。

### 9.3 回归测试

- 现有 `tests/test_playlist_delete.c`：确认筛选改动没有破坏删除后跳下一张。
- 现有 `tests/test_left_drag.c`：确认筛选条弹出不影响左键拖动逻辑。
- 手工回归：动图播放、幻灯片、全屏、旋转、删除/重命名、Everything 搜索。

### 9.4 内存与句柄

- Debug 下反复打开/关闭信息窗口 100 次，观察 GDI 对象数和内存。
- 反复收藏/取消收藏 1000 次，确认路径列表无泄漏。
- 反复输入筛选关键字 1000 次，确认防抖定时器正确停止。

## 10. 需要主人拍板的决策

1. **EXIF 做到哪一层？**
   - A. 只做 Windows 属性系统（覆盖 JPEG/TIFF/PNG 和装了扩展的 HEIC，工作量最小）。
   - B. 属性系统 + GDI+ 回退（覆盖更稳，推荐）。
   - C. 再加 HEIC 内置解析和 WebP EXIF（覆盖最全，工作量最大）。
2. **信息面板用哪种 UI？**
   - A. 两列 ListView（专业、对齐好，推荐）。
   - B. 只读多行文本框（实现最简单，列不对齐）。
3. **收藏夹存储位置？**
   - A. 继续放 `voidImageViewer.ini`（保持单文件便携，推荐）。
   - B. 单独 `voidImageViewer.favorites.txt`（便于手工编辑，但多一个文件）。
4. **最近打开保存时机？**
   - A. 退出时统一保存（推荐，避免频繁写 ini）。
   - B. 每次打开都保存（更抗崩溃，但写盘频繁）。

## 附录：参考的成熟方案

- IrfanView：Image Information / EXIF 信息窗口是**无模态**的，浏览其他图片时自动更新，记住窗口大小和位置，信息可选中复制。
- FastRawViewer：文件名筛选用 `Alt+F` 切换，出现编辑行，输入子串实时过滤。
- ACDSee：文件列表顶部 Quick Search 输入文件名前缀即时过滤。
- Windows 平台最近文件（MRU）：按最后访问时间排序，达到上限后移除最旧条目，常见上限 25。
- MFC `CRecentFileList`：从 ini/注册表读写 MRU 列表，是 Windows 桌面程序的经典做法。
- Microsoft 属性系统：`System.Photo.*`、`System.GPS.*`、`System.Image.*` 是读取 EXIF/GPS 的官方途径。
- GDI+ `Image::GetPropertyIdList` / `GetPropertyItem`：JPEG/TIFF 元数据的传统回退方案。
- Windows UX 指南：对话框重新显示时应恢复上次的大小、位置和状态；首次显示应在 owner 窗口上居中。
