# 02 架构设计文档（净室开发蓝图）

> 本文档描述新软件的**技术选型、模块划分与数据流**。AI 编码时应以本文档为蓝图。
> 注意：本文给出的是"思路与职责划分"，具体代码结构、命名、文件组织由 AI 自行设计。

## 1. 技术选型总纲

| 维度 | 选择 | 理由 |
|---|---|---|
| 语言 | C（C89/C99 风格，纯过程式） | 单 exe 体积小、启动快、无运行时框架依赖 |
| UI 框架 | 原生 Win32 API（窗口过程 + 消息驱动） | 零框架、毫秒级启动 |
| 绘制 | GDI（BitBlt/StretchBlt/AlphaBlend）+ GDI+ 仅用于加载与首帧位图生成 | 兼容老系统、无 D2D/D3D 依赖 |
| 字符串编码 | 内部统一 UTF-8，Win32 边界转 UTF-16（wchar） | ini/日志/UI 全 UTF-8，边界集中转换 |
| CRT | /MT 静态链接 | 单 exe 零依赖 |
| 图像解码 | GDI+ → libwebp → WIC → libheif+libde265 四级降级 | 常规格式走系统，WebP/HEIC 内置兜底 |
| 配置 | 自研 INI 解析器（UTF-8、单节） | 不引依赖 |
| 多语言 | 编译期字符串表（每语言一数组，ID 索引） | 无运行时文件依赖 |
| 安装 | NSIS 仅负责放文件，系统级动作由程序自身命令行完成 | 安装器逻辑可复用于绿色版 |
| 平台 | Windows 7+，x86/x64 | — |

### 1.1 性能与资源策略汇总（轻量卖点的技术保障）

| 策略 | 落点（详见对应章节） |
|---|---|
| 阻塞式消息循环（无消息即睡眠，空闲 CPU≈0） | §3 线程模型 / 03 §1 |
| 只重画可见区域 + mipmap 懒生成 + 放大只拉伸可见区段 + 超大图分块 | §5 渲染管线 |
| 运行期不保留原始像素；帧为 GDI 位图；边解码边播；预加载/缓存各仅 1 张 | §3 线程模型 / §8 播放列表 |
| 解码零拷贝（全局内存直供解码器） | §4 解码管线 |
| UI 浮层默认不创建（沉浸模式省 GDI 句柄）；按钮条纯绘制非控件 | §13 资源清单 / 03 §2 |
| /MT 静态单 exe、语言表编译进 exe | 本节技术选型 |
| 语言表单一定义（避免每编译单元复制数百 KB） | §9.2 本地化 |

明确**不采用**：分层窗口（WS_EX_LAYERED）、Direct2D/DirectX、双缓冲整页位图、资源文件菜单（MENU 资源）、外部语言 DLL。

```
│ · 状态栏       │ · 幻灯片与转场       │ · 安全内存/安全算术   │

│   gdiplus 集成 │ webp 解码层 │ wic 解码层 │ heif 解码层    │
├────────────────────────────────────────────────────────┤
│                 OS 封装层（按需动态加载 API）              │

```

模块职责要点：

- **main 模块**：全局状态唯一持有者（帧数组、播放列表、视图状态、定时器 ID 等）；所有 UI 回调归它。
- **解码层四兄弟**：签名一致的加载函数（输入：IStream；输出：帧数信息 + 逐帧 RGBA 回调），主程序对四者一视同仁。
- **OS 封装层**：所有"可能随系统版本变化"的 API 经函数指针动态加载；进程启动时一次性解析；同时负责防 DLL 劫持（限制系统 DLL 搜索路径）与浮点舍入模式定死。
- **左键拖拽决策**：做成**纯函数**（输入：有无平移余地/是否全屏/是否标题栏/是否最大化 → 输出：滚动/移窗/无动作），独立单元测试穷举。

## 3. 线程模型

```
UI 线程（唯一窗口线程）
   │  请求加载（描述当前目标文件的 WIN32_FIND_DATA + 是否预载）
   ▼
加载线程（单条，串行处理"最新请求"）
   │  读文件(顺序读、限2GB) → 全局内存 → IStream
   │  依次尝试：GDI+ → libwebp → WIC → libheif
   │  每帧：RGBA → alpha预混合 → 24bpp → HBITMAP → EXIF方向旋转 → mipmap预生成
   ▼
应答队列（临界区保护的链表）+ 自定义窗口消息通知
   │  消息类型：首帧(含宽高/帧数/预生成mipmap) / 追加帧 / 完成 / 失败
   ▼
UI 线程消化应答：挂帧数组、启动动画定时器、重绘
```

关键规则：
1. **新加载请求到来 → 先终止当前加载线程**（原子标志，解码与读文件循环中多点检查），再起新线程；被取消的请求排队为"下一个"。
2. 帧从解码到 UI **全程 HBITMAP**，运行期不再碰原始像素（旋转除外，旋转时重新生成）。
3. 边解码边播：UI 只依赖"已加载数"，不加载数之外的帧一律不碰。
4. 退出：原子置终止标志 → 等线程退出 → 才销毁窗口与释放 GDI+。

## 4. 解码管线（统一协议）

解码层统一协议（新实现自定具体形态，语义必须一致）：
- 输入：整个文件的内存流（零拷贝：全局内存直接锁出指针给 libwebp/libheif）。
- 信息回调：帧总数、画布宽高、有无 alpha。
- 帧回调：紧密排列的 32bpp RGBA 像素 + 帧延时(毫秒)；返回 0 表示 UI 要求中止。
- 像素约定：所有解码器出口统一 RGBA；WIC 出口是 BGRA 需换序；libheif 可能带行距 padding 需压平。
- 格式分派顺序：GDI+（jpg/png/gif/bmp/tif/ico；GIF 动画在此解）失败 → libwebp → WIC → libheif；每级失败容忍"至少解出 1 帧"即算成功。
- 帧延时来源：GDI+ 读帧延时属性（1/100 秒 ×10，属性坏数据防御 + 0 兜底成 100ms）；libwebp 用相邻帧时间戳差；WIC/HEIF 恒 0（静态）。
- 防线：宽×高×4 用 64 位校验 ≤ 约 2GB；文件 >2GB 直接拒绝。

## 5. 渲染管线

```
WM_PAINT
 ├─ 取"实际可见的更新区域"（拆成矩形列表，RTL 镜像）
 ├─ 计算理想渲染尺寸（主缩放档位 × Pan&Scan 系数）与目标位置
 │   （锚点百分比定位 + 拖拽偏移；默认锚点=居中）
 ├─ 从 mipmap 链选源：取"渲染尺寸 ≥ 该级一半"的最高分辨率级
 ├─ 每个可见矩形：
 │    · 尺寸恰好等于某级 → 直接 BitBlt
 │    · 缩小 → 平滑/最近邻 StretchBlt（复杂剪裁区逐矩形clip调用，避免整区域慢路径）
 │    · 放大 → 剪裁矩形对应的源区段先画到临时小位图再 BitBlt（避免整图拉伸开销）
 │    · 超大帧 → 分块拼接拉伸（GDI 单次拉伸有 32768 限制）
 ├─ 图片四周空白：按窗口/全屏两套背景色填充
 ├─ WM_ERASEBKGND 返回已处理（自绘背景防闪烁）
 └─ 叠加：转场淡入淡出（若进行中）→ 自绘按钮条 → 左上角文件名
```

Mipmap 链规则：
- 每帧挂一条逐级减半链（1/2、1/4、…直到 1×1），**懒生成**：绘制时发现目标渲染尺寸已低于下一级一半且该级不存在 → 当场从上一级用平滑方式缩出并缓存。
- 选择规则保证任何情况下最终拉伸倍率不超过 2 倍，兼顾画质与速度。
- 旋转作废整条链。

## 6. 视图状态模型（缩放/平移）

两套并存的缩放量：
1. **主缩放档位**（0..15）：0 档=适应窗口，最高档=约 16 倍；渲染尺寸 = 适应尺寸(或原图尺寸×16 基准) 按档位曲线内插。
2. **Pan&Scan 微调系数**（约 ±2%/档 的等比表，中心档=100%）乘在最终渲染尺寸上；另有**锚点百分比**(0..1000，默认 500=居中) 决定图片相对窗口定位，加上拖拽偏移量。

1:1 模式：临时态（进入时保存旧档位，退出恢复），此时直接用原图尺寸渲染。

视图偏移钳制规则：图片小于视口时可强制居中；大于视口时不露出超出边。

## 7. 定时器与动画

| 定时器 | 用途 | 实现要点 |
|---|---|---|
| 动画计时 | 动图逐帧推进 | 优先用高精度定时队列（1ms 周期，回调仅投递防重入消息）；不支持时退回系统定时器；用高精度计数器累计时间，一次 tick 可连跳多帧（追帧），跳帧计数 |
| 幻灯片计时 | 到点翻页 | 普通定时器；换图后重置 |
| 转场计时 | 淡入淡出重绘 | 约 15ms 周期；由流逝时间计算透明度 |
| 状态临时文字 | 3 秒后清除 | — |
| 隐藏光标 | 2 秒无操作 | 悬停探测定时器（可配） |

动画推进语义：按"累计时间 vs 帧延时×速率倒数"循环判断到点即推进，暂停只停推进不停计时清理；速率表 21 档（0.125x–8x）。

## 8. 播放列表与导航

- 结构：双向链表，节点持有查找数据（含文件属性）；每节点带单调递增的**加入序号**作排序最终并列依据（保证稳定排序）。
- 导航不做物理排序：按当前排序配置**实时比较找下一个/上一个**；找不到回绕。
- 比较器：名称=系统区域字符串比较 + 忽略大小写 + **数字按数值**（自然排序，Win7+）；大小/日期类并列时按名称升序稳定化。**默认排序 = 修改时间降序**（配置 sort=2 且 sort_ascending=0）。
- 预加载/缓存采用**平行的帧数组**：预载帧存"预载数组"，真翻到该文件时整块接管（首帧已到→零延迟切换；未到→标记"加载完成后激活"）；上一张缓存把完整加载的帧整体移入"缓存数组"。
- 随机模式（Everything 场景）：先请求总数，再以随机偏移请求 1 条；offset 越界按新总数重试。

## 9. 配置与多语言架构

### 9.1 INI
- 解析器：逐行读、跳 BOM、只认指定节、键入二叉树；读取按 int/string 两类。
- 双层位置：exe 目录 ini 为根（含 appdata 开关）；appdata=1 时再读 %APPDATA% 覆盖。
- 保存：全键序列化 → 临时文件 → 原子替换。
- 快捷键行：键名=英文菜单路径派生（保证跨语言稳定），值=逗号分隔十进制。

### 9.2 本地化
- 一个全局"当前语言索引"+ 每语言一张按 ID 排列的 UTF-8 字符串数组（编译期常量，单一定义点）。
- 取词：`表[语言][ID]`；越界即致命错误（Debug 断言）；分隔线用 -1。
- 语言检测：ini 值 → -1 时取系统 UI 语言主语言码映射 → 未知回退英语。
- **切换即时生效**四步：存 ini → 整棵重建主菜单并挂回窗口 → 刷新标题/状态栏/勾选 → 重建工具栏（若显示中）。对话框文本在打开时注入。
- RTL：仅主窗口加 RTL 布局扩展样式；切换时动态加/去 + 强制重算框架 + 全量重绘。

## 10. 菜单/命令/快捷键三位一体架构

- **命令表**（静态数据）：每条命令 = { 本地化 ID, 菜单标志(弹出/分隔/单选/隐藏), 菜单容器 ID, 命令 ID }。
- **菜单容器 ID 枚举**：18 个容器（主菜单 7 个一级 + 各子菜单）。
- 主菜单构建：遍历命令表，弹出项新建子菜单；普通项文案后拼 `\t快捷键文本`。
- 右键菜单：独立新建，按一个"右键条目序列"（命令 ID 与容器 ID 的混排，用成对容器 ID 模拟进出子菜单）展开，再挂接主菜单共享子菜单提供全量功能；销毁前摘下共享子菜单。
- 勾选/可用性：单一"刷新勾选"函数每次弹出前重算（启用/禁用 + 勾选 + 单选圆点）。
- 快捷键：内存中"命令→键列表"结构；消息循环**前置过滤器**统一拦截键盘消息匹配（支持长按重复语义）；侧键也在此层转译。
- 菜单项上的快捷键文本与实际键表同源，自定义后重建菜单自动更新。

## 12. 构建与安装架构

- 单一 VS 解决方案 + 单一工程；4 配置（Debug/Release × Win32/x64）；工具集随 VS 版本；/MT；/utf-8；Release 全速优化。
- 第三方库三种编法：
  1. libwebp：**解码子集源码直接进主工程**（只留 dec/demux/dsp/utils 中 x86/x64 相关单元）；
  2. libheif：CMake 预编译静态库（注意静态构建宏，否则按 dllimport 找符号失败）；
  3. libde265：CMake 预编译静态库，**x64 用 /O1**（MSVC /O2 优化器已知会编错其扫描表初始化导致花屏，用降优化绕开；用像素哈希对比验证 x86/x64 一致）。
  - 静态 CRT 链接第三方静态库时的对齐分配符号缺失：自写符号垫片补齐（HeapAlloc 多分配存原始指针）。
- 一键构建脚本：vswhere 定位 VS → 构建两个架构 → 失败即非零退出。
- NSIS：双语安装包；只解文件 + 以 `ExecWait` 调用程序自身安装开关（/install、关联开关等）；卸载把 exe 复制到临时目录再执行 /uninstall（避免自删运行中 exe）；读旧配置做升级安装。
