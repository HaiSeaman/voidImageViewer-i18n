## 这个版本解决了什么？

v3.2 是一次以「代码正确性与工程质量」为核心的加固版本。上一版（v3.1）的智能拖拽功能上线后，我们顺手对全仓库做了一次深度审计，挖出了 1 个严重崩溃 bug、3 个未定义行为/残留问题，并把多年积累的仓库脏东西全部清理干净。

### 最严重的修复：随机播放模式下删图会崩溃（use-after-free）

- **现象**：开启「随机播放 (Shuffle)」后，从播放列表中删除一张图片，之后翻动图片时会**随机崩溃或显示错误图片**。
- **根因**：删除时把「元素个数」误当成「字节数」传给了内存搬运函数（漏乘 `sizeof`），导致随机索引数组错乱，里面残留了指向已经释放内存的悬垂指针；下一次导航解引用它就是经典的使用已释放内存（use-after-free）。
- **修复**：补上缺失的 `sizeof` 因子，并新增独立的回归测试（`tests/test_playlist_delete.c`）——先用有缺陷的逻辑跑出失败，再验证修复后通过，确保这个 bug 永远不再回来。

### 另外三个修复

1. **状态栏像素颜色显示随机值**：光标不在图片上时，程序读取了未初始化的内存来计算 RGB（未定义行为）。现在先初始化为 0，颜色稳定。
2. **动画加载瞬间按「上一帧」会越界崩溃**：帧回退在动画还没加载完时可能把帧号算成 -1，访问数组的 -1 位置。现在钳位到第 0 帧，绝对安全。
3. **卸载软件后文件关联残留**：删除注册表关联用的 API 删不掉带子键的项，导致卸载后某些图片格式仍被指向已删除的程序。换成能整棵删除的 `SHDeleteKeyW`。

## 代码质量与工程卫生

- **合并重复代码**：Everything 搜索集成的「返回结果解析」和「搜索请求发送」之前分别有两份几乎相同的实现（共约 260 行），现在抽成公共函数，**所有安全边界校验（数据长度、偏移、越界防护）一个不丢**。
- **幻灯片倍速档位**：之前加一个档位要改四个地方，现在统一由一张表驱动，改一处即可。
- **删除死代码**：移除从未被编译的 `crt.c` / `crt.h` 死文件。
- **清理版本库**：84 个编译中间产物（.obj/.pdb/日志等）从 git 中移除（它们本应由构建重新生成）；删除仓库里 4 个过期的 v3.0 安装包。
- **修复版本号错乱**：exe 的底层版本信息之前显示的是远古的 1.0.0.16（字符串却是 3.1），现在数字与字符串统一为 3.2.0.0。

## 对用户完全无缝

- **不新增任何设置项**，不改变任何交互与界面，下载解压、用新 exe 覆盖旧版即可；
- 10 种界面语言零改动；
- 所有原有功能（看图、动画、幻灯片、Everything 联动、文件关联）行为完全不变。

## 质量验证

- **构建**：x64 与 x86 双平台 Release 全量重编译通过，零警告。
- **单元测试**：左侧拖拽判定 16/16 用例通过；删除播放列表回归测试 3/3 通过。
- **版本信息**：双平台 exe 的 Windows 文件属性均为 3.2.0.0。
